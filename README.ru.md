# 3x-ui-vpn-setup — Skill для ИИ-агента (v1.3)

> **Задолбали блокировки чужих VPN?** Подними **свой** сервер за один вечер — без ручного копания в конфигах.
>
> **Как это работает:** установи skill в ИИ-агента (Claude, Codex, Grok, Qwen…) и **просто отдай ему задачу**. Агент сам по SSH настроит 3X-UI, Reality, XHTTP, Hysteria2, при желании AmneziaWG 3.1, подписку и маршрутизацию Happ — а ещё защитит и будет проверять сервер. Тебе не нужно разбираться в Xray — достаточно дать доступ и домен.
>
> **Что нужно от тебя:**
> - IP VPS и **один домен** для VPN/CDN (для админ-панели публичная DNS-запись по умолчанию **не создаётся**)
> - **SSH-доступ** к серверу (лучше **ключ**, не пароль)
> - **Твои публичные IP-адреса** — они попадают в белый список, чтобы защита никогда не заблокировала тебя самого
> - **Sudo** на время настройки — лучше отдельная учётка агента: только ключ, с датой окончания (`references/agent-access-hygiene.md`)
>
> Всё остальное — сертификаты, inbound'ы, подписка, routing, блок-лист, мониторинг — делает агент по playbook внутри skill.

**Стек:** VLESS **Reality** + XHTTP + TCP Podkop + Hysteria2 (+ опционально **AmneziaWG 3.1**) + Happ routing (DoH) + nginx CDN fallback,
панель **только через SSH-туннель**, **самообновляющиеся сертификаты**, **блок-лист IPsum + Fail2Ban**.

## Что ты получишь на выходе

| Результат | Описание |
|-----------|----------|
| 4 профиля в подписке | Reality (основной), TCP, XHTTP, Hysteria2 |
| AmneziaWG 3.1 (по желанию) | Для роутера OpenWrt и приложений Amnezia; в подписку Happ не входит — отдаётся `.conf`/QR |
| Своя подписка | Кастомные пути, не `/sub/` как у всех |
| Split .ru | Российские сайты напрямую, остальное через VPN (только в Happ) |
| CDN-страница на :443 | Выглядит как обычный сайт, не «голый» VPN-порт |
| Панель недоступна из интернета | Заходишь через SSH-туннель |
| Сертификат продлевается сам | И проверяется — иначе тихо истекает через ~90 дней |
| Защита | IPsum (≈17 тыс. известных вредоносных IP) + Fail2Ban |
| Handoff | Агент отдаёт ссылки, пароли — в твой менеджер |

## Что нового в v1.3 (уроки реальной эксплуатации)

| Область | Что изменилось |
|---------|----------------|
| **Сертификаты** | Главный тихий сбой: acme.sh из 3X-UI продлевает в режиме *standalone* (нужен свободный порт 80), а там живёт nginx → через ~90 дней сертификат истекает, все TLS-профили падают, Reality работает — и всё выглядит как «заблокировали». Новые `deploy-acme-renewal.sh` (webroot + хук, тест на staging), `check-cert-expiry.sh`, проверка срока в `verify-server.sh` и мониторинге |
| **Защита по умолчанию** | IPsum в отдельной таблице nftables (белый список, автооткат, ежедневное обновление) + Fail2Ban `sshd` с `ignoreip` для админа |
| **Панель** | Не публичная: нет DNS-записи, порт закрыт, SSH-туннель + запись в hosts, самоподписанный сертификат |
| **Тестирование** | `loopback-test.py`: настоящий VLESS-хендшейк по каждому inbound на самом сервере — доказывает работоспособность независимо от «n/a» в клиенте |
| **AmneziaWG 3.1** | Опциональный модуль (`awg-tool.py`: создать / сменить обфускацию / выпустить `.conf`) |
| **API** | `api-reference.md` переписан под 3X-UI **3.9.0** (GET/POST, `openapi.json`, `inbounds/update` больше не меняет клиентов) |
| **Ловушки** | Таблица `hosts` переопределяет ссылки подписки; панель кэширует настройки; XHTTP+Reality не работал на Xray 26.7.28; копия вместо симлинка в `sites-enabled`; на Ubuntu 26.04 `sudo -E` игнорируется; `pkill -f` убивает собственную SSH-сессию |
| **Аудит** | `audit-server.sh` находит остатки учёток/sudo-правил/ключей, устаревшие конфиги, неверные ссылки |

Честные границы: что проверено вживую, а что нет — отмечено в каждом документе (`compatibility.md`).

## Принципы

- Не патчим бинарники 3X-UI / Xray — только панель, API, SQLite, UFW, nginx, nftables
- Reality — основной протокол, не голый TLS на 443
- Сначала доказать реальным хендшейком, потом винить (или откатывать) сервер
- Новый сервер → `execution-order.md`; починка → `repair-only.md`
- Секреты не попадают в публичный репозиторий; реальные имена хостов в примерах — только если готов сделать их публичными

## Безопасность доступа

| Вариант | Рекомендация |
|---------|--------------|
| SSH | Только **ed25519 ключ**, `PasswordAuthentication no` |
| Учётка агента | Отдельный пользователь, ключ, sudo `NOPASSWD`, дата окончания; после работы удалить |
| Панель | Случайный `webBasePath`, API-токен, **закрыта для интернета**, доступ через туннель |
| Защита | IPsum + Fail2Ban; свои IP — в белом списке до включения |
| После setup | Аудит учёток (`audit-server.sh`), ротация секретов, которые видел агент |
