# AmneziaWG 3.1 inside 3X-UI (optional module)

Native inbound type `amneziawg` (3X-UI **≥ 3.7.0**). Managed from the panel like any other protocol — no kernel module,
no DKMS, no Docker, no second panel. Verified end to end on 3X-UI 3.9.0 / Xray 26.9.30 / Ubuntu 26.04 (iPhone client;
OpenWrt router not verified by the author).

## How it works

* `amneziawg-go` runs **inside the panel process** over a userspace (gVisor) network stack.
* Each peer's decapsulated traffic is relayed into **its own loopback SOCKS5 inbound of Xray** (port
  `65100 + inbound id`, tagged with the AWG inbound's tag). So per-client stats, sniffing, access log and
  **Xray Routing rules apply to AWG clients like to any other protocol**; egress = the server's IP via Xray outbounds.
* Therefore **no `ip_forward`/NAT/iptables** work is needed (`net.ipv4.ip_forward=0` is fine). Only the UDP port in UFW.
* Transport is **UDP**. One vCPU shares crypto with Xray — measure speed after install.
* AWG is **not in the JSON/plain subscription** → it cannot be imported into Happ. Clients: AmneziaVPN /
  AmneziaWG apps (iOS/Android/desktop, must be 3.1-capable for 3.1 fields) or an OpenWrt AWG package. Delivery is
  a `.conf` file / QR / `vpn://` link.
* Client-side split routing (Happ's `.ru` direct profile) does **not** apply to AWG. Options: use AWG as a full tunnel
  on phones; on OpenWrt route selectively with your router tool (Podkop/Forkop "interface" mode — unverified).
  Server-side routing cannot give a "RU sites direct from the client" effect (traffic exits from the server anyway).

## Parameters and validation rules (from the panel docs and code)

| Field | Rule |
|-------|------|
| subnet | IPv4 tunnel subnet, must not overlap other inbounds (e.g. `10.66.66.0/24`); clients get `/32` (3.9: overlapping `allowedIPs` are rejected) |
| MTU | panel default `1420 − S4` ignores ContentPaddingAddition/RandomTrailers → set `1500 − 60 − S4 − maxPadding − 32` (≈1340) or packets fragment ("connected, nothing loads") |
| Jc / Jmin ≤ Jmax | junk packets before the handshake |
| S1 0..1552, S2 0..1608 | **`S1 + 56 ≠ S2`** forbidden |
| S3 0..1636, S4 0..32 | |
| H1–H4 | four **distinct, non-overlapping** values, > 4 (1–4 = vanilla WireGuard types; blank = 1/2/3/4 = easy to fingerprint). Prefer single values over ranges (amnezia-vpn/amneziawg-go#183 with RandomTrailers) |
| I1–I5 | optional signature packets (`<r N>`); generator fills only I1 |
| HeaderProtectionKey | base64 32 bytes, identical on all clients; **requires S1–S4 ≥ 12** |
| ContentPaddingAddition | number or range, keep ≤ 64 total |
| Rekey/Reject/Keepalive/Handshake timings | ranges; every RekeyAfterTime < every RejectAfterTime |
| RandomTrailers / DisableCookies | booleans |

The same values must exist on both ends: the server stores them once, client configs inherit them. After changing
obfuscation **every client config must be re-issued and re-imported**. A bad value keeps the interface from starting.

## Two profiles — go in this order

1. **`minimal`** (classic values, H blank, no 3.1 extras): a conservative starter that proves the **UDP path** to your
   VPS/hoster. Values taken from a public how-to for the same hoster class: `Jc=4 Jmin=48 Jmax=128 S1=20 S2=119 S3=55 S4=17`,
   MTU 1380, port 56100. Its author warned that other settings/ports gave "connects but no traffic" on his host.
2. **`full`** (generated AmneziaWG 3.1 set, `awg-tool.py` mirrors the panel's generator): stronger. Switch with
   `awg-tool.py rotate` once `minimal` is proven; change **one thing at a time** so a failure has one cause.

## Install (tool: `scripts/awg-tool.py`, run on the server)

```bash
export XUI_TOKEN=... XUI_BASE=/<webBasePath> XUI_HOST=<panel hostname = webDomain>
export AWG_PORT=56100 AWG_SUBNET=10.66.66.0/24 AWG_DNS=1.1.1.1,8.8.8.8 SHARE_ADDR=cdn.vpn.example.com
export AWG_REMARK="DE-AWG-3.1" AWG_CLIENTS=router,phone       # one client per device

sudo ufw allow ${AWG_PORT}/udp comment "AmneziaWG"
python3 scripts/awg-tool.py create --profile minimal --dry-run   # inspect the payload
python3 scripts/awg-tool.py create --profile minimal             # inbounds/add + clients/add
sudo python3 scripts/awg-tool.py render --host "$SHARE_ADDR" --out /root/awg --inbound <id>   # .conf files, mode 600, owner root
# fetch: sudo cat /root/awg/<email>.conf  (or copy to your own account), deliver securely, then delete from the server
```

Behind it: `POST /panel/api/inbounds/add` (protocol `amneziawg`, `settings.server` = obfuscation, `streamSettings: {}`),
`POST /panel/api/clients/add` with `inboundIds`; keys and `/32` addresses are generated by the panel; the server key
pair is **never** rotated on later saves. `keepAlive: 25` makes the `.conf` carry `PersistentKeepalive` (NAT).
Adding the inbound **restarts Xray** (one-second blip). `SHARE_ADDR` becomes the `Endpoint`; check the inbound's row in
the `hosts` table too (links/configs take the address from there, `gotchas.md`).

One client per device, **not** an existing VLESS client: a client attached to several tunnel inbounds gets separate
keys/addresses per inbound and had bugs in 3.7–3.8; separate clients also give separate stats and revocation.

## Verify (server side)

```bash
sudo ss -ulnp | grep :56100                      # listening, owned by x-ui
sudo ss -tlnp | grep 127.0.0.1:651               # relay port 65100+id owned by xray
curl -sk --resolve <panel-host>:<port>:127.0.0.1 -H "Authorization: Bearer $XUI_TOKEN" \
  -X POST https://<panel-host>:<port>/<webBasePath>/panel/api/server/amneziawglogs/50
#   running:true; events "started embedded interface awgN for inbound N"; peers[].endpoint appears after a client connects
sudo sqlite3 /etc/x-ui/x-ui.db "SELECT email,up,down FROM client_traffics WHERE email IN ('router','phone');"
```
The server cannot self-test the data path (no AWG client on it): success = a peer **endpoint** in the log and growing
client traffic. `scripts/loopback-test.py` skips AWG for that reason; still run it to confirm the other inbounds survived.

## Clients

* **Desktop (test first — separates "server/UDP path" from "router"):** AmneziaVPN, latest → import `.conf` → check external IP.
* **iPhone/Android:** AmneziaVPN/AmneziaWG, latest → QR from the panel's client dialog (config "Amnezia WG") or import the file.
  Which import form a given app version accepts was not verified. Old app version + 3.1 fields → blank the 3.1
  fields (the panel renders a config older clients understand) or update the app.
* **OpenWrt:** install an AWG 3.1-capable package, add an interface of type AmneziaWG, *Load configuration* from the `.conf`,
  check RX/TX. `AllowedIPs = 0.0.0.0/0` may turn the interface into the router's default route — if the whole LAN suddenly goes
  through the VPS, disable "Route Allowed IPs" on the interface and route via your policy tool (unverified detail).

## Troubleshooting "connected, no traffic"

UFW port · peer has no endpoint/handshake (obfuscation mismatch, client too old, port blocked) · MTU · return to `minimal` ·
try another port · client IP on the IPsum blocklist · test from another network (mobile data vs home).

## Rotate / roll back

```bash
python3 scripts/awg-tool.py rotate            # dry-run
python3 scripts/awg-tool.py rotate --apply    # new full set, keys/subnet/clients kept -> re-render + re-import all clients
```
Disable: `POST /panel/api/inbounds/setEnable/<id>` or `inbounds/del/<id>`, `ufw delete allow <port>/udp`. Back up `x-ui.db` first.
